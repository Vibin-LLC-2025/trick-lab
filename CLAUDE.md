# trick-lab

A small 3D skateboard flip-trick lab ("Land the trick"). A student sets pop height, flick rate and scoop rate, pops, watches the flight and the rider's feet, and the app recognizes the trick (kickflip, heelflip, backside and frontside pop shove-its, varial flip, 360 flip and more; flick and scoop are signed, ADR-30; no hardflip, ADR-41) and whether it landed. A game of SKATE against the computer (ADR-43, real-game rules ADR-44) sits on top: a coin flip, called sets, copy or take a letter, two tries on the last letter, no repeats. In a game you pop on a timing bar (ADR-65): the sliders say what you are going for, and how well you time the release decides how close you get; the computer goes through the same bar. Target (ADR-62, 2026-11-09): good hardware. High, a desktop or laptop with a real GPU, is what the game is designed for; Medium is for built-in graphics; Low is a frozen fallback for weak machines that gets no new features. The game of SKATE, the graphics, performance and how the game feels come first; the lab stays the exact, repeatable experiment. Keyboard and screen-reader users, always. The spec is `docs/BRIEF.md` (plus `docs/BRIEF-BOARD.md` for the realistic board and `docs/BRIEF-FEET.md` for the feet and quality tiers); the visual system is `docs/DESIGN.md`.

## Stack

React 19, TypeScript (strict, `noUncheckedIndexedAccess`), Vite, Zustand (one store, six slices), three.js via `@react-three/fiber`, `@react-three/drei` for `OrbitControls` and `useGLTF`. Vitest + React Testing Library + jsdom. ESLint with typescript-eslint and react-hooks. Node 22. Asset pipeline dev dependencies (pinned): `@gltf-transform/core`, `extensions` and `functions` 4.5.1, `meshoptimizer` 1.3.0, `@resvg/resvg-js` 2.6.2, `ktx2-encoder` 0.6.0 and `ktx-parse` 1.1.0 (KTX2 textures, ADR-49), `tsx` 4.23.15, `@types/node` 22. Browser checks: `@playwright/test` 1.64.1, pinned, Chromium only (ADR-61).

## Conventions (the rules a change must keep)

1. **Store actions own the event log.** Only actions in `src/store/` call `log()`. Components never append events, never compute objectives or recognize tricks. UI preferences (theme, quality, feet, legs, foot trails, speed, motion blur, sound, how you pop, the deck, the game's camera, the instant replay switch, the first game's walk-through being done) are never logged, and neither are the records (ADR-64), which only store actions write. A timed pop is the store's too (ADR-65): components call `pressPop`, and the bar reads the store's injected clock and scheduler, never a timer of its own. Sound cues (`soundCue`) come from store actions only, like announcements (ADR-58).
2. **The DOM owns accessibility.** The canvas is `aria-hidden`. Every action has a DOM control. `#scene-description` is the text equivalent of the scene (derived by `describeScene`). One polite live region (`Announcer`); messages come from store actions only.
3. **No drei `Html` or any DOM inside the Canvas.** UI goes in `src/ui/`. The game's cards over the stage (ADR-66) are page elements in a layer above it that takes no pointer events itself, and they are opaque, so no text sits on the 3D picture.
4. **Demand frameloop.** `frameloop` is `"always"` only while `status === 'playing'`, the welcome screen's preview plays (`previewAnimates`, ADR-45) the board rolls in a game (`rollMoves`, ADR-67: from the start of a go until it has stopped after the landing, held by a pause or a dialog) a game's landing plays out (`landingMoves`, ADR-68) or the instant replay plays (`replayMoves`, ADR-72), `"demand"` otherwise. Once everything has come to rest no frame is drawn (the browser check counts none between one and three seconds after rest). Any store change requests one frame (`InvalidateOnStoreChange`). Anything that changes the picture outside the store (the environment map, a GLB arriving) calls `invalidate()` once.
5. **FlightDriver is the only `useFrame` that writes a pose.** On the welcome screen it poses the preview from `showcase.ts` and leaves the store's flight alone (ADR-45). Elsewhere it keeps progress, the board pose and the feet pose in refs, applies them to the Board's outer group, the two shoe groups and the shadow disc, sets the foot trails' playhead uniform, commits progress to the store at most 10 times a second, and calls `land()` at progress 1. It also runs the roll (ADR-67, `scene/roll.ts`): speed and distance from the store's `roll`, written into the ground's textures and the wheels' print (texture offsets, no draw call) and the skate spot's place (`sceneryX`, ADR-69), and `rollRested()` when a slowing board stops; and the landing's motion in a game (ADR-68, `sim/settle.ts`, `scene/landingMove.ts`): two pairs of groups round the board and round the rider make its rigid move, a bail's board falls (its roll and height) and the feet are cleared against it, and `landingDone()` when it has played out; and the instant replay (ADR-72): the shown flight again from `scene/replayClock.ts`, slowed, without the landing's motion, and `endReplay()` at its end. Board, BoardModel, BoardPrimitive, Feet, ShoesModel, ShoePrimitive and FootPaths have no per-frame code; the foot-trail geometry is rebuilt only when the shown flight changes. PerfProbe is the only other `useFrame`: it makes the one render call (through the effects' `frame.render` where the tier has them, ADR-51) and measures it, and while a flight plays writes each frame's interval into the preallocated `trickFrames` for the automatic step-down (ADR-59).
6. **No per-frame allocation.** No `new`, array or object literals inside `useFrame`. `writePose` and `writeFeetPose` mutate one object each; the store state is passed as the inputs object.
7. **Shared resources.** Procedural geometry and materials live in `scene/resources.ts` (a custom shader exists twice: GLSL there for WebGLRenderer, TSL in `nodeRenderer.ts` for WebGPURenderer, both reading the shared `uniforms`, ADR-50; the legs' dither too, ADR-60), merged per material, disposed each time a Canvas unmounts (`SharedResources` in TrickScene; a tier change remounts the Canvas, and a renderer's dispose listeners on a shared material hold its programs until then, ADR-61). Never put `<boxGeometry>` or `<meshStandardMaterial>` JSX in scene components. The GLB's geometries, materials and textures belong to the useGLTF cache: render them with `dispose={null}` and never dispose them from a component.
8. **Scene numbers live in `scene/artDirection.ts`.** No color, intensity, camera or renderer literal elsewhere in `src/scene`; the per-tier renderer settings are `ART.quality`, the effects' numbers `ART.post`. `SCENE_BG` per theme must equal `--scene-bg` in `tokens.css` (tested). Board asset numbers live in `src/asset/spec.ts` (`ART.board.restY` reads `REST_Y` from it), shoe numbers in `src/asset/shoeSpec.ts`, and the feet model's `FOOT` must equal the shoe's `SHOE` size (tested).
9. **Class names follow the contract in `docs/BRIEF.md`** (plus `.app__still` from DESIGN.md 14.6, `.celebration`, `.celebration__shout`, `.celebration__trick` and `.skate__letter--new` from DESIGN.md 14.7, `.toggle__state`, the `.skate__*` classes from DESIGN.md 11, the `.skate__bar*` classes from DESIGN.md 11.1, the `.hud__*` classes from 11.2 and the `.lesson*` classes from 11.3, the `.tricks*` classes from DESIGN.md 12.4, `.objective__text`, `.view-panel__actions`, the `.segmented*` classes and the `.foot-steps*` and `.foot-step*` classes from DESIGN.md). Do not invent styling classes.
10. **Focus management goes through the store.** Actions call `requestFocus`; `App` applies it. After reset, focus is on the setup heading; after a screen change, on the new screen's h1 (`#screen-heading`); when a game starts, ends or is quit, on the game's heading (`#skate-heading`, ADR-46: the end is the one place a resolved trick moves focus, because the turn controls are gone). Applying a preset and resolving a trick never move focus.
11. **Physics stays pure.** `src/sim` imports nothing from React, three, the store or `src/asset`. Flick and scoop are signed: the magnitude is the rate, the sign the direction (positive kickflip and backside, negative heelflip and frontside, ADR-30); positive inputs must keep the poses pinned in `feet.pinned.test.ts`. Presets are asserted in `tricks.test.ts` to land clean at pop 0.35 m and fail at 0.15 m. A landing has a grade (ADR-63, `landing.ts`): clean, sketchy or bail; `isLanded` alone decides land or bail, and a clean landing's feet are the pinned poses exactly. A release of the timing bar scales the flick and the scoop and may pass the sliders' limits, up to about 4.2 rev/s (`bar.ts`, ADR-65): the model and the feet clearance are tested there. The feet model (`feet.ts`) is driven by the inputs and the flight, never by the recognized result; it decides land or bail with the same `isLanded` rule recognition uses.
12. **Writing:** no em-dashes in code, copy or docs. Absolute dates (2026-11-04). Model names as aliases (fable, opus).
13. **The assets are generated, never hand-edited.** Change `src/asset/` (or the design SVGs), run `npm run assets`, and commit the GLBs with the source change. `src/asset/` imports three's geometry classes but nothing from React, the store or `src/scene`. A test fails if a committed GLB no longer matches its geometry source.
14. **Budgets are gates, not goals.** The frame-time targets (ADR-62, PERF-BUDGET.md "Targets"; the measurement's last table checks them on the reference machine): graphics time per frame under 4 ms on High, 3 ms on Medium, 2 ms on Low; the app's own work under 4 ms; no frame longer than 16.7 ms after the first second. Draw calls with every switch on: under 60 on High, 40 on Medium, 20 on Low, enforced by `npm run test:browser` with the expected worst case (`LEDGER` in `browser/helpers.ts`), which changes only in the commit of a step that adds or removes a draw. `npm run assets:check` (in `verify`) enforces `BUDGETS` in `src/asset/spec.ts` per file: the Medium board 300 KB, 8 draw calls, 25,000 triangles, 4 textures at 1024 px; the High board 2.5 MB, 8 draw calls, 120,000 triangles, 6 textures at 2048 px; the shoes 600 KB, 3 draw calls, 30,000 triangles, 2 textures at 1024 px; the ground 500 KB, 1 draw call, 64 triangles, 3 textures at 1024 px; the spot 300 KB, 1 draw call, 15,000 triangles, 3 textures at 1024 px (ADR-69). All fail on textures not power of two, not mipmapped or not KTX2 with a full mip chain (ADR-49), on missing meshopt or quantization, on Draco, and on size or rest height drifting. `npm run bundle:check` (in `verify`, after `vite build`) enforces the download budget in `scripts/lib/bundleBudget.ts`: what each first visit downloads, listed per tier, theme and feet, compressed as GitHub Pages sends it, per file and per visit (High 1,721 KB, Medium 1,216 KB, Low 431 KB). A new file needs a budget of its own. Do not raise a limit to pass; say why in an ADR if it must change (ADR-16 is the last time it did).
15. **No Draco, no CDN decoders.** Models load through `useModel` in `scene/gltf.ts` (drei's `useGLTF` with Draco off and meshopt on): the meshopt decoder is bundled, and the KTX2 transcoder is three's own, which Vite emits into the build with a content hash (ADR-49, its 2026-11-09 update): served from this site, one copy. School networks block CDNs.

## Verify loop

1. Make the change.
2. `npm run verify`, and for a change to the 3D view or the game `npm run test:browser` after it. Fix until green. Do not weaken a test to pass it; if behavior changed on purpose, change the test in the same commit and say why.
3. For anything visual or 3D: `npm run dev` (or `npm run build && npm run preview` for numbers), then check in a browser with the global `playwright-cli` using a named session (`-s=<task>`), over HTTP, and close it by name. Look at console errors, press `p` in the lab for the perf badge (draw calls must stay under 60 on High, 40 on Medium and 20 on Low, ADR-62; a step that adds one says so and moves `LEDGER`), check that the frame counter stops when the board lands, and drive the flow by keyboard only. `?debug` in the URL exposes the R3F store as `window.__trickLab`; call `.get()` on it for the live state (`gl.info`, `scene`, `controls`). Check all three quality tiers and the feet on and off.
4. `@playwright/test` is a pinned dev dependency for the browser checks only (the owner's yes, 2026-11-09, ADR-61): Chromium only, never upgraded or given another browser without asking. Looking at the app by hand still goes through the global `playwright-cli`. Do not install system tools (for example `toktx`) without asking.

## Reviewing agent output

Treat agent changes as a pull request from a capable stranger. Before accepting:

- Run `npm run verify` yourself; do not trust a pasted summary.
- Read the diff of `src/store/` first. Any component that calls `log`, sets `events`, computes objectives or calls `recognize` is a reject.
- Grep for `new ` and `{` or `[` literals inside `useFrame` callbacks, any second `useFrame` that touches the board or the feet, `<.*Geometry` and `<.*Material` JSX in `src/scene`, and `Html` from drei.
- Check that new interactive DOM has an accessible name, a visible focus style from `app.css`, and an announcement where state changes.
- Check that tests drive real behavior (real store, keyboard via user-event). New mocks beyond the canvas stub need a reason.
- For a GLB change: the `assets:check` table, the triangle and size deltas in the `npm run assets` output, and a screenshot of the board. A binary diff alone is not reviewable.
- Reject drive-by refactors, new dependencies, and style changes in `src/styles/` from implementation agents.
- Scope agents narrowly (one slice or one component) and give them the file list and the rules above.
