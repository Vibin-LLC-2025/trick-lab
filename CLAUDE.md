# trick-lab

A small 3D skateboard flip-trick lab ("Land the trick"). A student sets pop height, flick rate and scoop rate, pops, watches the flight, and the app recognizes the trick (kickflip, pop shove-it, varial flip, 360 flip and more) and whether it landed. Target: low-end Chromebooks, keyboard and screen-reader users. The spec is `docs/BRIEF.md` (plus `docs/BRIEF-BOARD.md` for the realistic board); the visual system is `docs/DESIGN.md`.

## Stack

React 19, TypeScript (strict, `noUncheckedIndexedAccess`), Vite, Zustand (one store, four slices), three.js via `@react-three/fiber`, `@react-three/drei` for `OrbitControls` and `useGLTF`. Vitest + React Testing Library + jsdom. ESLint with typescript-eslint and react-hooks. Node 22. Asset pipeline dev dependencies (pinned): `@gltf-transform/core`, `extensions` and `functions` 4.5.1, `meshoptimizer` 1.3.0, `@resvg/resvg-js` 2.6.2, `tsx` 4.23.15, `@types/node` 22.

## Conventions (the rules a change must keep)

1. **Store actions own the event log.** Only actions in `src/store/` call `log()`. Components never append events, never compute objectives or recognize tricks. UI preferences (theme, board detail) are never logged.
2. **The DOM owns accessibility.** The canvas is `aria-hidden`. Every action has a DOM control. `#scene-description` is the text equivalent of the scene (derived by `describeScene`). One polite live region (`Announcer`); messages come from store actions only.
3. **No drei `Html` or any DOM inside the Canvas.** UI goes in `src/ui/`.
4. **Demand frameloop.** `frameloop` is `"always"` only while `status === 'playing'`, `"demand"` otherwise. Any store change requests one frame (`InvalidateOnStoreChange`). Anything that changes the picture outside the store (the environment map, the GLB arriving) calls `invalidate()` once.
5. **FlightDriver is the only `useFrame` that writes the board pose.** It keeps progress and pose in refs, applies the pose to the Board's outer group and the shadow disc, commits progress to the store at most 10 times a second, and calls `land()` at progress 1. Board, BoardModel and BoardPrimitive have no per-frame code. PerfProbe is the only other `useFrame` and only measures.
6. **No per-frame allocation.** No `new`, array or object literals inside `useFrame`. `writePose` mutates one object.
7. **Shared resources.** Procedural geometry and materials live in `scene/resources.ts`, merged per material, disposed when the Canvas unmounts. Never put `<boxGeometry>` or `<meshStandardMaterial>` JSX in scene components. The GLB's geometries, materials and textures belong to the useGLTF cache: render them with `dispose={null}` and never dispose them from a component.
8. **Scene numbers live in `scene/artDirection.ts`.** No color, intensity or camera literal elsewhere in `src/scene`. `SCENE_BG` per theme must equal `--scene-bg` in `tokens.css` (tested). Board asset numbers live in `src/asset/spec.ts`; `ART.board.restY` reads `REST_Y` from it.
9. **Class names follow the contract in `docs/BRIEF.md`** (plus `.toggle__state`, `.objective__text`, `.view-panel__actions` and the `.segmented*` classes from DESIGN.md). Do not invent styling classes.
10. **Focus management goes through the store.** Actions call `requestFocus`; `App` applies it. After reset, focus is on the setup heading. Applying a preset and resolving a trick never move focus.
11. **Physics stays pure.** `src/sim` imports nothing from React, three or the store. Presets are asserted in `tricks.test.ts` to land at pop 0.35 m and fail at 0.15 m.
12. **Writing:** no em-dashes in code, copy or docs. Absolute dates (2026-11-04). Model names as aliases (fable, opus).
13. **The asset is generated, never hand-edited.** Change `src/asset/` (or the design SVG), run `npm run assets`, and commit the GLB with the source change. `src/asset/` imports three's geometry classes but nothing from React, the store or `src/scene`. A test fails if the committed GLB no longer matches the geometry source.
14. **Budgets are gates, not goals.** `npm run assets:check` (in `verify`) fails on more than 300 KB, 8 draw calls, 25,000 triangles or 4 textures, on textures over 1024 px, not power of two or not mipmapped, on missing meshopt or quantization, on Draco, and on the board's size or rest height drifting. Do not raise a limit to pass; say why in an ADR if it must change.
15. **No Draco, no CDN decoders.** `useGLTF(url, false, true)`: meshopt only, its decoder is bundled. School networks block CDNs.

## Verify loop

1. Make the change.
2. `npm run verify`. Fix until green. Do not weaken a test to pass it; if behavior changed on purpose, change the test in the same commit and say why.
3. For anything visual or 3D: `npm run dev` (or `npm run build && npm run preview` for numbers), then check in a browser with the global `playwright-cli` using a named session (`-s=<task>`), over HTTP, and close it by name. Look at console errors, press `p` for the perf badge (draw calls must stay under 20), check that the frame counter stops when the board lands, and drive the flow by keyboard only. `?debug` in the URL exposes the R3F store as `window.__trickLab`; call `.get()` on it for the live state (`gl.info`, `scene`, `controls`). Check both board detail levels.
4. Do not install Playwright in this project. Do not install system tools (for example `toktx`) without asking.

## Reviewing agent output

Treat agent changes as a pull request from a capable stranger. Before accepting:

- Run `npm run verify` yourself; do not trust a pasted summary.
- Read the diff of `src/store/` first. Any component that calls `log`, sets `events`, computes objectives or calls `recognize` is a reject.
- Grep for `new ` and `{` or `[` literals inside `useFrame` callbacks, any second `useFrame` that touches the board, `<.*Geometry` and `<.*Material` JSX in `src/scene`, and `Html` from drei.
- Check that new interactive DOM has an accessible name, a visible focus style from `app.css`, and an announcement where state changes.
- Check that tests drive real behavior (real store, keyboard via user-event). New mocks beyond the canvas stub need a reason.
- For a GLB change: the `assets:check` table, the triangle and size deltas in the `npm run assets` output, and a screenshot of the board. A binary diff alone is not reviewable.
- Reject drive-by refactors, new dependencies, and style changes in `src/styles/` from implementation agents.
- Scope agents narrowly (one slice or one component) and give them the file list and the rules above.
