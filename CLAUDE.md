# trick-lab

A small 3D skateboard flip-trick lab ("Land the trick"). A student sets pop height, flick rate and scoop rate, pops, watches the flight and the rider's feet, and the app recognizes the trick (kickflip, heelflip, backside and frontside pop shove-its, varial flip, 360 flip and more; flick and scoop are signed, ADR-30; no hardflip, ADR-41) and whether it landed. Target: a desktop with a real GPU by default, with quality tiers down to low-end Chromebooks; keyboard and screen-reader users. The spec is `docs/BRIEF.md` (plus `docs/BRIEF-BOARD.md` for the realistic board and `docs/BRIEF-FEET.md` for the feet and quality tiers); the visual system is `docs/DESIGN.md`.

## Stack

React 19, TypeScript (strict, `noUncheckedIndexedAccess`), Vite, Zustand (one store, four slices), three.js via `@react-three/fiber`, `@react-three/drei` for `OrbitControls` and `useGLTF`. Vitest + React Testing Library + jsdom. ESLint with typescript-eslint and react-hooks. Node 22. Asset pipeline dev dependencies (pinned): `@gltf-transform/core`, `extensions` and `functions` 4.5.1, `meshoptimizer` 1.3.0, `@resvg/resvg-js` 2.6.2, `tsx` 4.23.15, `@types/node` 22.

## Conventions (the rules a change must keep)

1. **Store actions own the event log.** Only actions in `src/store/` call `log()`. Components never append events, never compute objectives or recognize tricks. UI preferences (theme, quality, feet, foot trails, speed) are never logged.
2. **The DOM owns accessibility.** The canvas is `aria-hidden`. Every action has a DOM control. `#scene-description` is the text equivalent of the scene (derived by `describeScene`). One polite live region (`Announcer`); messages come from store actions only.
3. **No drei `Html` or any DOM inside the Canvas.** UI goes in `src/ui/`.
4. **Demand frameloop.** `frameloop` is `"always"` only while `status === 'playing'`, `"demand"` otherwise. Any store change requests one frame (`InvalidateOnStoreChange`). Anything that changes the picture outside the store (the environment map, a GLB arriving) calls `invalidate()` once.
5. **FlightDriver is the only `useFrame` that writes a pose.** It keeps progress, the board pose and the feet pose in refs, applies them to the Board's outer group, the two shoe groups and the shadow disc, sets the foot trails' playhead uniform, commits progress to the store at most 10 times a second, and calls `land()` at progress 1. Board, BoardModel, BoardPrimitive, Feet, ShoesModel, ShoePrimitive and FootPaths have no per-frame code; the foot-trail geometry is rebuilt only when the shown flight changes. PerfProbe is the only other `useFrame` and only measures.
6. **No per-frame allocation.** No `new`, array or object literals inside `useFrame`. `writePose` and `writeFeetPose` mutate one object each; the store state is passed as the inputs object.
7. **Shared resources.** Procedural geometry and materials live in `scene/resources.ts`, merged per material, disposed when the Canvas unmounts. Never put `<boxGeometry>` or `<meshStandardMaterial>` JSX in scene components. The GLB's geometries, materials and textures belong to the useGLTF cache: render them with `dispose={null}` and never dispose them from a component.
8. **Scene numbers live in `scene/artDirection.ts`.** No color, intensity, camera or renderer literal elsewhere in `src/scene`; the per-tier renderer settings are `ART.quality`. `SCENE_BG` per theme must equal `--scene-bg` in `tokens.css` (tested). Board asset numbers live in `src/asset/spec.ts` (`ART.board.restY` reads `REST_Y` from it), shoe numbers in `src/asset/shoeSpec.ts`, and the feet model's `FOOT` must equal the shoe's `SHOE` size (tested).
9. **Class names follow the contract in `docs/BRIEF.md`** (plus `.toggle__state`, `.objective__text`, `.view-panel__actions`, the `.segmented*` classes and the `.foot-steps*` and `.foot-step*` classes from DESIGN.md). Do not invent styling classes.
10. **Focus management goes through the store.** Actions call `requestFocus`; `App` applies it. After reset, focus is on the setup heading. Applying a preset and resolving a trick never move focus.
11. **Physics stays pure.** `src/sim` imports nothing from React, three, the store or `src/asset`. Flick and scoop are signed: the magnitude is the rate, the sign the direction (positive kickflip and backside, negative heelflip and frontside, ADR-30); positive inputs must keep the poses pinned in `feet.pinned.test.ts`. Presets are asserted in `tricks.test.ts` to land at pop 0.35 m and fail at 0.15 m. The feet model (`feet.ts`) is driven by the inputs and the flight, never by the recognized result; it decides land or bail with the same `isLanded` rule recognition uses.
12. **Writing:** no em-dashes in code, copy or docs. Absolute dates (2026-11-04). Model names as aliases (fable, opus).
13. **The assets are generated, never hand-edited.** Change `src/asset/` (or the design SVGs), run `npm run assets`, and commit the four GLBs with the source change. `src/asset/` imports three's geometry classes but nothing from React, the store or `src/scene`. A test fails if a committed GLB no longer matches its geometry source.
14. **Budgets are gates, not goals.** `npm run assets:check` (in `verify`) enforces `BUDGETS` in `src/asset/spec.ts` per file: the Medium board 300 KB, 8 draw calls, 25,000 triangles, 4 textures at 1024 px; the High board 2.5 MB, 8 draw calls, 120,000 triangles, 6 textures at 2048 px; the shoes 600 KB, 3 draw calls, 30,000 triangles, 2 textures at 1024 px; the ground 500 KB, 1 draw call, 64 triangles, 3 textures at 1024 px. All fail on textures not power of two or not mipmapped, on missing meshopt or quantization, on Draco, and on size or rest height drifting. Do not raise a limit to pass; say why in an ADR if it must change (ADR-16 is the last time it did).
15. **No Draco, no CDN decoders.** `useGLTF(url, false, true)`: meshopt only, its decoder is bundled. School networks block CDNs.

## Verify loop

1. Make the change.
2. `npm run verify`. Fix until green. Do not weaken a test to pass it; if behavior changed on purpose, change the test in the same commit and say why.
3. For anything visual or 3D: `npm run dev` (or `npm run build && npm run preview` for numbers), then check in a browser with the global `playwright-cli` using a named session (`-s=<task>`), over HTTP, and close it by name. Look at console errors, press `p` for the perf badge (draw calls must stay under 20 on Low and Medium, under 40 on High where the shadow pass counts), check that the frame counter stops when the board lands, and drive the flow by keyboard only. `?debug` in the URL exposes the R3F store as `window.__trickLab`; call `.get()` on it for the live state (`gl.info`, `scene`, `controls`). Check all three quality tiers and the feet on and off.
4. Do not install Playwright in this project. Do not install system tools (for example `toktx`) without asking.

## Reviewing agent output

Treat agent changes as a pull request from a capable stranger. Before accepting:

- Run `npm run verify` yourself; do not trust a pasted summary.
- Read the diff of `src/store/` first. Any component that calls `log`, sets `events`, computes objectives or calls `recognize` is a reject.
- Grep for `new ` and `{` or `[` literals inside `useFrame` callbacks, any second `useFrame` that touches the board or the feet, `<.*Geometry` and `<.*Material` JSX in `src/scene`, and `Html` from drei.
- Check that new interactive DOM has an accessible name, a visible focus style from `app.css`, and an announcement where state changes.
- Check that tests drive real behavior (real store, keyboard via user-event). New mocks beyond the canvas stub need a reason.
- For a GLB change: the `assets:check` table, the triangle and size deltas in the `npm run assets` output, and a screenshot of the board. A binary diff alone is not reviewable.
- Reject drive-by refactors, new dependencies, and style changes in `src/styles/` from implementation agents.
- Scope agents narrowly (one slice or one component) and give them the file list and the rules above.
